# Chirp-start reference and 1/2-Hz selection — 2026-10-27

The user requests the visual flash to coincide with the **start**, rather than
the centre, of the chirp. The audio-only experiment now defaults to that
reference (`0x23`), explicitly distinguished from the earlier centre-reference
packet (`0x21`). The receiver accepts both after CRC validation. Synthesis and
the matched filter still use a centre internally; the protected timestamp and
reported reception time use the declared reference. No 15-ms reinterpretation
of historical recordings is applied.

## Validation

```sh
python3 tests/audio-timecode/run.py --out /tmp/avsync-onset-20261027 --packets 128 --seed 20261027
python3 tests/audio-timecode/test_reference.py /tmp/avsync-onset-20261027/audio-timecode-probe
python3 tests/audio-timecode/run.py --binary /tmp/avsync-onset-20261027/audio-timecode-probe --anchor centre --out /tmp/avsync-centre-compat-20261027 --packets 8 --seed 20261027
```

- [Start-reference matrix](results-2026-10-27-start.json): 128 packets per source,
  93 rows, three profiles (1200/1 Hz, 600/1 Hz, 1200/2 Hz). Every complete packet
  decoded in all 25 non-extreme-noise positive channel conditions per profile.
  This includes actual G.711 A/µ-law, phone filters, AGC, Opus, drift, echoes,
  40-ms data loss and random joining. Zero wrong payloads and zero accepted
  packets in all wrong-CRC/legacy/noise/tone controls. All mandatory gates passed.
- Stress failures remain: at 0-dB SNR, 1200/1 Hz decoded 55/128, 1200/2 Hz 51/128,
  and 600/1 Hz 128/128; at −6 dB all profiles decoded 0/128. The payload/header
  and seed differ from the dated centre benchmark; these counts do not isolate
  an effect of changing the timing reference.
- [Centre compatibility matrix](results-2026-10-27-centre-compat.json): 8 packets
  per source through the same 93-row matrix, all mandatory gates passed. The
  historical independent wire vector still matches Python struct/zlib.
- Dedicated regression passed for 1200 baud at both 1 and 2 Hz, both references,
  both actual G.711 codecs, a known +35-ms arrival delay, exact payload fields,
  identical chirp waveforms, exactly 15-ms difference between transmitted start
  and centre timestamps, mixed-reference blind decoding, and rejection of bad
  rates, conflicting periods, non-finite values and 600-baud 2-Hz overlap.
  Arrival tolerance was 0.15 ms in those synthetic filtered G.711 cases; this
  does not establish physical phone accuracy.

## Availability

`generate --event-rate 1|2` selects the rate. 1200 baud supports either;
600 baud supports only 1/s for this full 25-byte candidate. `--anchor centre`
is an explicit compatibility option. Result JSON records source and binary
hashes; the older dated report/listening files are preserved unchanged.

The released generator already supports `AVSYNC_EVENT_RATE=1|2` (also legacy
4/s). The new audio-only format is still local, experimental and uncommitted;
it is not deployed or integrated into the phone. This harness has no video:
a white pulse starting on every chirp, compatible picture-tracker updates,
and a visible rate selector in the main Signal panel remain integration work.
The legacy marker alternates black/white. Compact 17/15-byte packets remain a
proposal. Actual acoustic/call/WebRTC paths and physical timing remain untested.
